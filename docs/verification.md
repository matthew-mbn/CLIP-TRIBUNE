В реальном окне мастер создал тестовый исходник, отдельный worker-процесс выполнил анализ и экспорт двух 15-секундных MP4 720×1280. ## EXE 0.2.0 и TikTok

Сборка PyInstaller 6.22.3, Python 3.15.2, один `dist/CLIP TRIBUNE.exe`, Windows x64.
Внутри Python/Tk, зависимости, иконка ICO и FFmpeg/FFprobe. Пользовательские данные и ключи не упакованы.
`--self-check` выполнен из временной рабочей директории, PATH ограничен Windows/System32,
STORAGE_ROOT и порт выделены отдельно: **exit 0, ok=true**.
Поднялись API и multiprocessing worker; созданы два настоящих 15-секундных MP4 1080×1920,
H.264 + звук, 30 fps. Все 10 страниц CustomTkinter созданы и получили ответы реального API.
Отчёт текущей проверки: `build/exe-check.json`. Дочерние процессы завершились после проверки.

TikTok: 16 контрактных тестов без внешних публикаций. Проверены hex PKCE, одноразовый state,
разделение callback Google/TikTok, обмен кода, шифрование и ротация токенов, scope/consent,
параметры Direct Post, запрет повторного задания, размер частей, inbox/direct upload,
отдельные статусы передачи/публикации, неизвестный адрес загрузки, сбой без повторного init,
локальная авторизация и глобальная остановка. Живая отправка в TikTok/YouTube не проверена:
credentials и согласие на конкретную публикацию отсутствуют.

Финальный EXE также запущен в обычном режиме с рабочим пространством AppData.
Проверены первый запуск, готовность FFmpeg, главный экран, название CLIP TRIBUNE,
собственный значок заголовка Windows и формы Inbox / Direct Post. После исправления
иконки тест всех страниц снова прошёл. Приложение оставлено открытым.
Размер: 123090525 байт (около 117.4 МиБ); точный SHA256 хранится рядом в dist.
