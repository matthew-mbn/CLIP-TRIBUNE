# Как разбирать CLIP TRIBUNE, изучая Python

Это не один большой скрипт: каждая часть отвечает за свою задачу. Начните с понятного сценария и постепенно двигайтесь глубже.

## 1. Окно и виджеты

Откройте `desktop/theme.py`. Здесь константы цветов, функция `logo()` и помощники `field()`, `button()`, `table()`. Поменяйте цвет `RED` и перезапустите приложение: это безопасное первое упражнение.

Затем `desktop/app.py`. Класс `Application` наследуется от `customtkinter.CTk` — современной оболочки над стандартным `tk.Tk`. Метод `build_shell()` создаёт боковую панель. `show_page()` уничтожает прежнюю страницу и создаёт новую из словаря `PAGES`. Все элементы по-прежнему написаны на Python: `CTkButton`, `CTkFrame`, `CTkEntry` похожи на стандартные кнопки, контейнеры и поля Tkinter, но умеют рисовать скругления и тёмную тему.

`StringVar` связывает строку Python с полем или надписью. `command=` хранит функцию, которая выполнится при нажатии. Важно передавать функцию, а не вызывать её сразу: `command=self.create`, а не `command=self.create()`.

## 2. Нажатие «Создать нарезки»

В `desktop/source_pages.py` найдите `StudioPage.create()`:

1. `tree.selection()` возвращает ID выбранных строк.
2. Значения полей собираются в обычный словарь `dict`.
3. `self.call()` отправляет его в локальный API.
4. После успеха открывается очередь.

Проследите путь: `Page.call()` → `Application.async_call()` → `desktop.client.request()` → `POST /api/jobs`.

## 3. Зачем фоновый поток

Tkinter рисует окно в главном потоке. Если там вызвать долгий HTTP-запрос, окно перестанет отвечать. Поэтому `ThreadPoolExecutor` выполняет запрос в фоне, а `queue.Queue` возвращает результат главному потоку. Метод `receive_results()` вызывается через `after()` и уже безопасно меняет виджеты.

Попробуйте добавить новую надпись о состоянии операции. Не обновляйте виджеты непосредственно в функции, переданной `executor.submit()`.

## 4. Ввод → схема → сервис → таблица

В `backend/schemas.py` класс `RenderOptions` задаёт допустимые значения. Например, `Field(ge=15, le=60)` означает диапазон длительности. FastAPI проверяет данные до запуска обработчика.

`backend/api.py` принимает запрос. `backend/services.py` проверяет наличие исходника и права, создаёт `RenderJob` и вызывает `session.commit()`. Таблица описана в `backend/models.py`.

`Session` — единица работы с базой. Пока изменения не подтверждены `commit()`, другой процесс не обязан их видеть. `rollback()` отменяет изменения текущей транзакции после ошибки.

## 5. Очередь и процессы

`backend/worker.py` запускается отдельно от окна. `claim_job()` атомарно меняет `pending` на `analyzing`. Условие `WHERE status = 'pending'` не позволяет двум воркерам взять одно задание.

`process_job()` анализирует видео, выбирает фрагменты, рендерит их и записывает результаты. При ошибке статус становится `failed`, а при явной отмене — `cancelled`. Отмена имеет собственный класс исключения `Cancelled`.

На Windows новый процесс импортирует модуль заново. Поэтому запуск защищён `if __name__ == '__main__':`; без этой проверки можно случайно создать бесконечную цепочку процессов.

## 6. Анализ и FFmpeg

В `backend/video.py` прочитайте функции в порядке `probe()` → `analyze()` → `select_candidates()` → `render()`.

- `probe()` читает JSON от FFprobe.
- `analyze()` сравнивает маленькие серые кадры и измеряет RMS звука.
- `select_candidates()` сортирует окна по оценке и удаляет пересечения.
- `render()` собирает список аргументов FFmpeg, запускает процесс и проверяет готовый файл.

Мы передаём список аргументов в `subprocess.Popen`, не строку shell-команды. Это и безопаснее, и проще для путей с пробелами.

## 7. Тесты как учебные примеры

`tests/test_video.py::test_full_pipeline_and_publish_queue` показывает полный сценарий без кликов. `assert` выражает ожидаемое поведение. `pytest.fixture` готовит исходные условия; `monkeypatch` временно заменяет внешний сервис.

Небольшие упражнения:

1. Добавьте новую цветовую тему через словарь цветов.
2. Покажите длительность исходника в формате `мин:сек`.
3. Добавьте фильтр «Оценка выше 50» в библиотеку.
4. Добавьте тест, что фрагменты не выходят за длительность исходника.
5. Добавьте новый объяснимый признак оценки и проверьте его на собственном материале.

Меняйте одну функцию за раз, запускайте подходящий тест, затем открывайте приложение. OAuth, квоты и отмена затрагивают внешние действия — изучайте их на mock-тестах, прежде чем проверять на настоящем канале.

## 8. TikTok и сборка EXE

Откройте `desktop/tiktok_page.py`: словари связывают понятные названия полей с параметрами API.
`backend/tiktok.py` показывает OAuth, работу с JSON, чтение файла порциями и сохранение статуса.
Успешная передача файла и успешная публикация — разные события, поэтому для них разные статусы.
`tests/test_tiktok.py` позволяет изучать это без аккаунта и без отправки видео в интернет.

`launcher.py` умеет запускать окно и дочерние службы. В EXE `sys.executable` указывает на сам EXE,
поэтому дочерние службы выбираются параметром `--service`. `multiprocessing.freeze_support()`
передаёт управление дочерним процессам рендера. `backend/config.py` разделяет временные ресурсы
сборки и постоянные пользовательские данные. `clip_tribune.spec` перечисляет включаемые ресурсы.

Логотип описан простыми фигурами в `scripts/build_brand.py`: из них строятся PNG, SVG и ICO.
Запуск `build_windows.ps1` собирает новый файл `dist/CLIP TRIBUNE.exe` после ваших изменений.

## 9. Два экрана и реклама

В `backend/composition.py` функция `build()` собирает список аргументов FFmpeg и граф фильтров.
Она не запускает процессы: результат передаётся в `backend/video.py`, где уже есть отмена,
ограничение памяти и проверка готового MP4. Так проще менять композицию, не переписывая очередь.

Проследите путь: `RenderOptions` → `services.create_jobs()` → `worker.process_job()` → `video.render()`.
Нижний исходник и параметры рекламы сохраняются в `job.options`. Это снимок настроек: изменение
формы после постановки задания не меняет его результат. Поля `path` берутся из импортированных
материалов в базе, а не из присланного клиентом JSON.

Фильтр `vstack` ставит два кадра друг над другом. `colorkey` делает выбранный цвет прозрачным,
а `overlay` накладывает вставку. `setpts` задаёт её начало, `trim` ограничивает длительность.
`tests/test_composition.py` декодирует кадры результата и проверяет цвета в нужные секунды.
Звуковые тесты измеряют частоты, чтобы отличать верхнюю дорожку от нижней.

Упражнение: добавьте новое положение рекламы, сначала описав ожидаемую координату в тесте.

## 10. Скачивание и процессы

В `backend/downloads.py` функция `validate_url()` принимает только ссылки на отдельные видео.
`_download()` работает в дочернем процессе и пишет небольшой JSON с прогрессом. Родительская
функция `download()` следит за отменой и завершает всё дерево своих процессов при остановке.
Tkinter получает прогресс через API и не зависает, пока сеть или FFmpeg заняты.

`tests/test_downloads.py` проверяет входные ссылки, права, повторные запросы и сохранение исходника
без сетевых обращений. Для полного EXE есть `scripts/packaged_check.py`; сетевые проверки
включаются отдельно переменной `CLIP_TRIBUNE_CHECK_DOWNLOADS=1`.
